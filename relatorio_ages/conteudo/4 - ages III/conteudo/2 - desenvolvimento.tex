\section{Desenvolvimento do Projeto}

\subsection{Repositório do Código Fonte do Projeto}

O projeto \textbf{VínculoHub Portal} foi organizado em um repositório principal no GitHub, contendo as aplicações de \textit{frontend} e \textit{backend}, a documentação técnica, os arquivos de infraestrutura e os scripts de apoio ao desenvolvimento.

\begin{itemize}
\item Repositório principal: \url{https://github.com/VinculoHub-Portal/VinculoHubPortal}
\end{itemize}

A estrutura do repositório foi dividida principalmente entre as pastas \texttt{frontend}, \texttt{backend} e \texttt{docs}. A pasta \texttt{frontend} concentrou a aplicação web utilizada pelos diferentes perfis de usuário. A pasta \texttt{backend} reuniu a \ac{API}, as regras de negócio, a integração com banco de dados, autenticação, documentos e serviços externos. A pasta \texttt{docs} foi utilizada para registrar materiais de apoio, validações de \textit{sprint}, tarefas refinadas e a modelagem do banco de dados.

Além disso, o projeto possui arquivos de orquestração e infraestrutura, como \texttt{docker-compose.yml}, \texttt{docker-compose.dev.yml}, \texttt{docker-compose.swarm.yml} e \texttt{main.tf}, evidenciando uma preocupação com padronização de ambiente, execução local e preparação para \textit{deploy} em nuvem.

\subsection{Banco de Dados Utilizado}

O banco de dados utilizado no projeto foi o \textbf{PostgreSQL}. A aplicação também utilizou \textbf{Flyway} para versionamento e execução das migrações do banco, permitindo que a estrutura fosse reproduzida de forma consistente nos ambientes de desenvolvimento e \textit{deploy}.

A Figura~\ref{fig:vinculohub-banco-dados} apresenta a modelagem. O banco foi documentado em formato \ac{DBML} no arquivo \texttt{docs/db/vinculo\_hub.dbml}. Entre as principais entidades modeladas estão usuários, \ac{ONGs}, empresas, projetos, documentos, editais, \ac{ODS}, endereços, denúncias e vínculos entre empresas e projetos.

A entidade \texttt{users} armazena os dados básicos do usuário e mantém integração com o Auth0 por meio do campo \texttt{auth0\_id}. As entidades \texttt{npo} e \texttt{company} representam, respectivamente, \ac{ONGs} e empresas cadastradas na plataforma. A entidade \texttt{project} centraliza os projetos cadastrados pelas \ac{ONGs}, enquanto \texttt{document} armazena metadados de arquivos vinculados a \ac{ONGs} ou projetos. A tabela \texttt{company\_project} representa os vínculos entre empresas e projetos, com status como pendente, em negociação, ativo ou inativo.

\subsection{Arquitetura Utilizada}

A Figura~\ref{fig:vinculohub-arquitetura} apresenta a infraestrutura documentada. A arquitetura do projeto foi baseada em uma aplicação web separada em \textit{frontend}, \textit{backend}, banco de dados e serviços externos. O \textit{frontend} se comunica com o \textit{backend} por meio de \ac{API} \ac{REST}. O \textit{backend} centraliza as regras de negócio, validações, persistência dos dados, segurança e integrações externas. O banco PostgreSQL armazena os dados relacionais da aplicação.

A autenticação e autorização foram integradas ao \textbf{Auth0}, com separação de perfis por \textit{roles}, como \texttt{COMPANY}, \texttt{NPO} e \texttt{ADMIN}. Essa separação permitiu controlar o acesso às rotas e funcionalidades específicas de empresas, \ac{ONGs} e administradores.

O projeto também utilizou \textbf{Docker Compose} para execução local dos serviços, incluindo \textit{backend}, \textit{frontend}, banco PostgreSQL e Flyway. Para armazenamento de arquivos, como documentos e editais, foi prevista integração com \textbf{\ac{AWS} \ac{S3}}. A documentação e os arquivos de infraestrutura também indicam uma organização voltada a \textit{deploy} em ambiente \ac{AWS}, com uso de \ac{EC2}, Docker Swarm, Elastic Block Storage e bucket \ac{S3}.

\subsection{Protótipos das Telas Desenvolvidas}

Entre os fluxos contemplados estavam o cadastro de \ac{ONGs}, cadastro de empresas, \textit{dashboards} por perfil, mural de editais, perfil público de \ac{ONGs}, perfil público de empresas, cadastro e edição de projetos, upload de documentos, denúncias e gestão de vínculos.

No \textit{frontend}, esses fluxos foram implementados em páginas e componentes específicos, como \texttt{AdminDashboard}, \texttt{CompanyDashboard}, \texttt{OngProfilePage}, \texttt{OngPublicProfilePage}, \texttt{ProjectDetailsPage}, \texttt{EditaisMuralPage}, \texttt{MyRelationshipsPage} e páginas administrativas para \ac{ONGs}, vínculos e notificações.

\subsection{Tecnologias Utilizadas}

No \textit{frontend}, React organizou a interface em componentes, TypeScript apoiou a verificação de tipos e Vite forneceu ferramentas de desenvolvimento e construção da aplicação. Material UI ofereceu componentes de interface e Tailwind \ac{CSS} apoiou a estilização \cite{react,typescript,vite,mui,tailwind}.

React Router organizou a navegação; React Query apoiou a consulta e o gerenciamento de dados remotos; Axios foi utilizado nas requisições \ac{HTTP}. A integração de autenticação foi apoiada pelo \ac{SDK} do Auth0. Para a qualidade da interface, Vitest foi empregado na execução de testes, Testing Library na verificação de componentes e Playwright em cenários de ponta a ponta \cite{router,query,axios,auth0,vitest,testinglibrary,playwright}.

No \textit{backend}, Java 17 e Spring Boot sustentaram a \ac{API} e as regras de negócio. Os módulos Spring Web, Spring Data \ac{JPA} e Spring Security apoiaram, respectivamente, os \textit{endpoints}, a persistência e a segurança, incluindo a validação de acesso com OAuth2. PostgreSQL armazenou os dados e Flyway controlou as migrações. Lombok foi utilizado para reduzir código repetitivo, e Swagger/OpenAPI para a documentação das operações \cite{spring,jpa,security,postgres,flyway,lombok,vinculohub}.

Na infraestrutura, Docker e Docker Compose padronizaram a execução dos serviços. Os arquivos Terraform descreveram recursos de infraestrutura, enquanto os serviços \ac{AWS} foram utilizados no contexto de implantação e armazenamento, incluindo \ac{S3} para documentos. Esses recursos precisam ser diferenciados das funcionalidades de negócio implementadas no sistema \cite{docker,terraform,aws}.

Na qualidade do \textit{backend}, o projeto utilizou JUnit para testes, Testcontainers para dependências em ambiente isolado e JaCoCo para cobertura, conforme o registro técnico do projeto. Spotless apoiou a formatação; PMD e SpotBugs realizaram análise estática. A presença dessas ferramentas no projeto não significa, por si só, que todos os cenários de uso tenham sido validados \cite{junit,testcontainers,jacoco,spotless,pmd,spotbugs,vinculohub}.
