\subsection{Banco de Dados Utilizado}
 \href{https://tools.ages.pucrs.br/certifica-o-por-meio-de-blockchain/blockchain-wiki/-/wikis/Banco-de-Dados}{Documentação do banco de dados na wiki do projeto.}

Para a aplicação utilizamos PostgreSQL como banco de dados relacional. A modelagem contemplou as entidades Certificado, Empresa, Usuário e Permissão e seus relacionamentos, além da necessidade de registrar \textit{logs}. Firebase foi utilizado para autenticação, uma responsabilidade distinta da persistência dos dados de negócio no PostgreSQL \cite{postgres,firebase,blockchain}.

\subsection{Arquitetura Utilizada}
 \url{https://tools.ages.pucrs.br/certifica-o-por-meio-de-blockchain/blockchain-wiki/-/wikis/arquitetura}

 \url{https://tools.ages.pucrs.br/certifica-o-por-meio-de-blockchain/blockchain-wiki/-/wikis/infraestrutura}

O sistema foi organizado em três camadas: \textit{frontend}, \textit{backend} e \textit{blockchain}. As operações solicitadas pela interface passavam pelo \textit{backend}, que intermediava o acesso à \textit{blockchain} e aos dados da aplicação. Essa separação concentrou o tratamento das requisições e as integrações externas no servidor.

A Figura~\ref{fig:blockchain-arquitetura} apresenta os componentes da solução, identificada como AuthLink na documentação. A separação entre interface, \ac{API}, banco de dados e \textit{blockchain} evidencia o papel do \textit{backend} na intermediação das operações solicitadas pelos usuários.

\subsection{Tecnologias Utilizadas}
TypeScript apoiou a verificação de tipos, React compôs as telas e Java 21 com Spring Boot sustentou o \textit{backend} \cite{typescript,react,java,spring}.

PostgreSQL armazenou os dados e Spring Data \ac{JPA} apoiou a persistência. Lombok reduziu código repetitivo e Firebase apoiou a autenticação \cite{postgres,jpa,lombok,firebase}.

Solidity foi utilizada nos contratos de certificação no Ethereum \cite{ethereum,solidity}.
